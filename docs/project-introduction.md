# 浮伴项目简介

## 项目定位

浮伴（Floating Pet）是一款面向桌面工作场景的全模态陪伴应用。它住在桌面边缘，平时保持安静；用户明确开启会话和输入来源后，它可以把当前画面、用户语音和文字上下文放进同一轮协助中。

项目对应的参考命题是“OpenHarmony Agent 鸿蒙原生智能多模态个人助理”。当前可直接评审的产品形态是 Windows Electron Demo，同时保留 OpenHarmony NEXT PC 的 ArkWeb/ArkTS 适配工程。

## 要解决的问题

用户遇到报错、任务中断或重复尝试时，通常需要离开当前工作区，再重新整理背景并输入给助手。这个过程会丢失上下文，也会把“我只是想继续工作”变成一次完整的聊天操作。

浮伴把入口放回桌面，但把主动权留给用户。它不会因为桌宠常驻就自动采集输入，也不会因为一次线索出现就直接打断用户。重复线索被确认后，它先询问是否需要协助，用户接受后才进入协助卡。

## 核心流程

1. 桌宠以透明置顶窗口常驻桌面，支持拖拽、边缘吸附、托盘和键盘操作。
2. 用户点击开始陪伴，应用进入陪伴状态，输入仍保持关闭。
3. 用户分别授权麦克风、摄像头或指定屏幕，并可以随时暂停采集。
4. 相同线索再次出现后，浮伴弹出可拒绝的询问。
5. 用户接受后进入 Chat 或 Realtime 协助流程，可以继续追问。
6. 勿扰、停止实时、暂停采集和结束陪伴都会释放对应输入链路。

除对话外，产品还提供记忆查看、修改和删除，用户确认后的称呼、目标与偏好持久化，任务、便签和专注计时等桌面工作辅助能力。

## MiniCPM-o 的作用

Electron 客户端负责桌面窗口、权限、会话状态、本地数据和 UI。Python 适配服务负责把客户端输入整理成模型服务请求。

- Chat：文字，以及经过校验的 JPEG 视觉帧和短 WAV 音频。
- Realtime：16 kHz 音频输入、JPEG 视觉帧、增量文字事件和 24 kHz 音频输出。
- 客户端：把模型返回结果放回协助卡，并支持用户继续追问或停止。

模型负责多模态理解和生成，外围系统负责权限、状态、记忆、业务规则和用户控制。这种拆分让产品在模型服务不可用时仍可以展示完整的桌面交互，也方便继续适配 OpenHarmony。

## OpenHarmony 延伸

OpenHarmony NEXT PC 工程复用当前 Renderer，通过 ArkWeb 承载同一套产品交互，并使用 ArkTS 能力桥接系统侧能力。仓库提供适配说明、预览 HAP 和当前构建边界，具体设备安装依赖签名与开发环境。

## 可验证性

评委可以直接运行 Windows 便携 Demo，或使用在线 Web Demo 查看离线交互。真实模型链路需要配置模型服务后验收。所有 Fake 场景都保留明确的 Fake/离线边界，不将确定性占位回复包装成任意屏幕理解或真实语音效果。
